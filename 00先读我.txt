一、这个包是什么
--------------------------------------------------------------------------------
· 可运行的**源码快照**（tripcraft 后端 + frontend 前端 + data 固定案例 + scripts 验收/启动脚本
  + tests + docs 文本）+ **最新前端构建**（frontend/dist）。
· 现场演示用：固定案例（香港黄先生 · 云南 5 日）的**逐步脚本与字段复制表**（见 _交接文档/演示脚本与说明/）。
· 选定**验收证据**（_交接文档/验收证据/）：两模式最终复验 JSON、桌面窗口 JSON、生产构建日志、
  浏览器全流程 progress.json、关键截图与 4 份客户 PDF。
· **可选**的成品演示库快照（_交接文档/成品数据可选恢复/）：只含成品账号与其已完成订单，
  用于查看订单 9000000000000009；不含登录会话，不含其它账号。

二、两种启动模式（**入口千万别搞混**）
--------------------------------------------------------------------------------
1) 普通模式（默认；随机游客 + 真实模型链路）
     双击仓库根  司南礼客桌面版.bat
     等价于：scripts\desktop_launch.ps1 -Mode Normal
     · 后端 127.0.0.1:18020 · 前端 127.0.0.1:5190 · 库 .dsh-run\normal\preview.sqlite
     · **不做任何固定案例替换**；演示时不要用它。
2) 内部标准入口 / 演示模式（工作人员显式运行）
     powershell -NoProfile -ExecutionPolicy Bypass -File .\启动标准演示.ps1
     等价于：scripts\desktop_launch.ps1 -Mode Demo（薄壳只做命名参数转发）
     · 后端 127.0.0.1:18930 · 前端 127.0.0.1:15191 · 库 .dsh-run\codex-review\preview.sqlite
     · 启动期声明：TRIPCRAFT_SCENARIO_MODE=offline + TRIPCRAFT_DEMO_TOURIST=on
       （+ TRIPCRAFT_BOOTSTRAP_ORDERS=1）→ 服务端把随机游客替换成固定黄先生。
两种模式都打开**真实的 Electron 本地应用窗口**（不是浏览器标签页），各自一份桌面 profile，
端口 / 库 / 会话互不影响；不要用 Vite 网页入口冒充桌面。

三、新机器第一次运行（**不能解压即跑**，先做这一步）
--------------------------------------------------------------------------------
包内 scripts\desktop_launch.ps1 里的 Python / Node 路径是打包机上的绝对路径
（C:\Users\Lenovo\...\python.exe 与 C:\Program Files\nodejs\node.exe）。换机后请先执行：

    powershell -NoProfile -ExecutionPolicy Bypass -File .\_交接文档\首次安装与适配.ps1

它会：① 在本机定位 python / node / npm；② **只改包内副本**的启动脚本路径；
③ 安装依赖（frontend 跑 npm ci；后端 pip install 本项目依赖）；④ 打印下一步命令。
本包**不含 node_modules**（体积原因），所以第一次必须先 npm ci。
适配脚本只改这个包里的文件，不会动你机器上其它工程。

四、现场演示怎么走（固定值全在脚本里）
--------------------------------------------------------------------------------
工作人员先启动演示模式（第二节第 2 条）→ 现场按普通流程：
    注册 → 12 题初测 → C6.1 学习（练到 ≥60 解锁换车事件）→ 消息中心待接单里选
    **黄先生 / 云南** → 抢单 → 文字首呼 → 四份文档 → 行中事件 → 行后结算/评分/画像
**不再需要任何「导入标准案例」页面**：注册初始单就是那张固定单。
逐步每一句填值、12 题逐题答案、逐日行程、报价/结算每一行、事件回复原文：
    _交接文档\演示脚本与说明\完整演示脚本.txt
复制用字段表（带复制按钮）：
    _交接文档\演示脚本与说明\演示字段复制表.html
说明：固定单**不会**因为你先做初测/学习而超时丢单（演示实例里未接单的固定单可续期；
已抢单/已完成不回退）。公开界面没有「标准案例」按钮，普通用户看不到内部入口。

七、真实限制（如实说明）
--------------------------------------------------------------------------------
1. **换机要先跑适配脚本**（第三节），否则启动脚本里的 python/node 绝对路径不对。
   版本要求：Python >= 3.11；Node.js >= 22.12.0（推荐 24.x，前端 electron 的 engines 要求）。
2. 包内**不含 node_modules、.git、.dsh-run 运行目录、运行日志/缓存、local.env 或任何密钥**；
   前端 dist 是最新构建产物，后端依赖需 pip 安装。
3. 成品库快照是**可选**的：只含成品账号与该订单（sessions 已清空、其它账号未纳入），
   恢复时会**拒绝覆盖**已存在的库；不恢复也能用「从零重演」走完整流程。
4. 未验证范围：真实语音（需麦克风与语音密钥）；**真实模型（live）档未在本包验证**（需自备密钥）；
   **换机环境尚未实机验收**——适配器与恢复器只做了静态检查与逻辑校验，没有在另一台干净机器上跑过
   安装；本包不包含 PPT。
5. 本包是从**运行中**的工程做的只读快照，未修改原工程与运行中的服务。
6. 根目录的 `一键启动.bat` / `停止服务.bat` 是**历史开发辅助**（旧 web 开发入口 / .runtime 停服流程），
   **不是**桌面演示的启动或停服入口；桌面只用 司南礼客桌面版.bat（普通）与 启动标准演示.ps1（演示）。
7. 「标准入口」只在**工作人员演示时**替代随机游客；普通本地 Electron 应用路径（司南礼客桌面版.bat）保持
   原样，永远走随机游客 + 真实模型链路。
