TripCraft 司南礼客 · 01 使用说明（新机器安装 / 两入口 / 现场演示 / 常见问题 / 备份恢复）
================================================================================
适用：Windows 10/11 + PowerShell 5.1（或 PowerShell 7）+ **Python >= 3.11** +
      **Node.js >= 22.12.0（推荐 24.x；前端 electron 的 engines 要求）**
包根目录示例：D:\交接\司南礼客-交接包-20261017

--------------------------------------------------------------------------------
1. 第一次安装（换机必做；不能解压即跑）
--------------------------------------------------------------------------------
1.1 安装系统依赖
    · Python 3.11 或更高（安装时勾选 Add python.exe to PATH）
    · Node.js 22.12 或更高（推荐 24.x，含 npm）
    · 校验：在 PowerShell 里执行
          python --version
          node --version
          npm --version
1.2 一键适配本包（只改包内副本）
          cd <包根目录>
          powershell -NoProfile -ExecutionPolicy Bypass -File .\_交接文档\首次安装与适配.ps1
    它会：定位并**校验**本机 python（>=3.11，自动跳过 WindowsApps 占位解释器）与 node（>=22.12.0）→
    改写包内 scripts\desktop_launch.ps1 的两个绝对路径并**回读确认** →
    在 frontend 目录执行 npm ci（包内不含 node_modules）→
    执行 python -m pip install -e .（后端依赖：fastapi / pydantic / uvicorn / websocket-client /
    websockets / reportlab）→ 打印下一步命令。
    npm 缺失或 frontend\package-lock.json 缺失会直接报错；npm ci / pip 非零退出会**直接失败**，
    不会出现「装失败还打印适配成功」。只想改路径不装依赖：加 -SkipInstall。
    要跑开发/测试（pytest、httpx）：用 -WithDev 重跑（= pip install -e ".[dev]"）。
1.3 前端构建（可选）：包内已带最新 frontend/dist，日常开发改前端时再构建
          cd frontend
          npm run build      # 产物写回 frontend\dist

--------------------------------------------------------------------------------
2. 两种启动模式（入口别搞混）
--------------------------------------------------------------------------------
2.1 普通模式（默认；随机游客 + 真实模型链路）
          cd <包根目录>
          双击  司南礼客桌面版.bat
          或：  powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\desktop_launch.ps1 -Mode Normal
    · 后端 127.0.0.1:18020 / 前端 127.0.0.1:5190 / 库 .dsh-run\normal\preview.sqlite
    · 不设任何演示开关 → 新账号拿到的是随机游客（例如「客户 K」），**不是**黄先生。
2.2 内部标准入口 / 演示模式（工作人员显式运行）
          cd <包根目录>
          powershell -NoProfile -ExecutionPolicy Bypass -File .\启动标准演示.ps1
    · 后端 127.0.0.1:18930 / 前端 127.0.0.1:15191 / 库 .dsh-run\codex-review\preview.sqlite
    · 启动期声明 TRIPCRAFT_SCENARIO_MODE=offline + TRIPCRAFT_DEMO_TOURIST=on
      （+ TRIPCRAFT_BOOTSTRAP_ORDERS=1）→ 服务端把随机游客替换成固定黄先生。
    · 只加 -WebOnly 时仅起服务、不开窗口（排障用）；-SelfCheck 用独立 profile 打开自检窗口。
2.3 两模式的共同点与区别
    · 共同：都是**真实 Electron 本地应用窗口**（不是浏览器标签页）；都走同源 /api；
      第二次启动只聚焦已有窗口；关闭窗口不结束后台服务；入口不会结束任何未知进程。
    · 区别：端口 / 数据库 / 桌面 profile 各自独立；只有演示模式会替换游客。
    · 复用规则：入口用运行目录里的 instance.json 与**真实进程身份**（mode/port/pid/创建时间/库/
      演示开关）核对后才复用；不一致会直接报错并提示按同一个库重启后端。**不要删除 instance.json。**
    · 不要用 Vite 页面入口（npm run dev 的 5190/15191 网页）冒充桌面档；排障可以，正式演示用两入口。

3. 现场固定演示（林晓 / 黄先生 云南 5 日）
--------------------------------------------------------------------------------
3.1 准备：工作人员先起演示模式（2.2）。公开界面**没有**「标准案例」按钮，也不需要任何导入页。
3.2 现场顺序（每一步的固定填值见 _交接文档\演示脚本与说明\完整演示脚本.txt）：
      注册（demo-linxiao-replay-20261017 / LvyuanDemo#2026，现场演示注册）→
      12 题初测（逐题答案在脚本里）→ C6.1 讲义 + 做题 5 轮（教学掌握度 25→60，解锁换车事件）→
      消息中心待接单里选 **黄先生 / 云南**（难度写「固定难度（不随画像浮动）」）→ 抢单 →
      文字首呼（opening 与逐句回复见脚本）→ 需求确认单 / 行程方案 V1→客户反馈→改 D4→V2→客户确认 /
      分项报价 / 合同与保险 / 出团通知书 → 行中事件 4 起逐会话回复 → 地接结算核对单 →
      成本与结算（定责已自动为资源方，点顶部按钮到「已结账留档」）→ 回访与复盘 → 生成本单评分 →
      11 条待复核逐条采纳 → 画像前后对比 → 导出 PDF。
3.3 关键口径（脚本内也写了）：
      · 报价 12690（人均 3173），报价时预估成本 10850 / 预估毛利 1840；
      · 结算按资源方组合报价成本 11030，实际毛利 1660（13.08%），损失 0；
      · 客户已收定金 3000 → 尾款 9690；临时换车 400 全部由车队承担（我方 0）；
      · 固定单不会因学习等待而丢单（未接单可续期；已抢单/已完成不回退）。
3.4 复制用字段表：_交接文档\演示脚本与说明\演示字段复制表.html（双击用浏览器打开；
      每个字段/每行都有「复制」按钮，不支持剪贴板时会回退为选中复制）。

5. 数据保存 / 备份 / 恢复
--------------------------------------------------------------------------------
5.1 库文件位置
    · 普通模式：<包根>\.dsh-run\normal\preview.sqlite
    · 演示模式：<包根>\.dsh-run\codex-review\preview.sqlite
5.2 备份（不要直接复制正在使用的库文件；用 SQLite 一致性备份）
    python -X utf8 -c "import sqlite3,sys;s=sqlite3.connect('file:<库路径>?mode=ro',uri=True);d=sqlite3.connect('backup.sqlite');s.backup(d);d.close();s.close()"
5.3 恢复成品演示库（可选，**要在首次启动演示模式之前做**）
    见 _交接文档\成品数据可选恢复\恢复说明.txt 与 恢复成品演示库.ps1：
    · 只恢复「成品账号 + 订单 9000000000000009」的快照；目标存在时**拒绝覆盖**（File.Copy
      overwrite:false），复制前请自行备份现有库；
    · 标准入口**只认固定位置** .dsh-run\codex-review\preview.sqlite；用 `-Target` 写到别的路径
      只是**保存一份备份**，标准入口不会自动使用它（文档里不再暗示换 -Target 就能登录看成品）；
    · 不要在服务运行中改名/替换库：先恢复，再启动演示。
5.4 从零重演（没有快照也能演）
    用未注册过的 demo- 前缀账号现场注册即可（演示实例里注册初始单就是固定单）；
    若要在旧账号上重来：页面重置只删当前账号数据，重置后必须重做 12 题初测 + 重练 C6.1 ≥60，
    再到「消息中心 → 获取新派单」让服务端重新下发固定单（没有导入页）。

6. 常见问题 / 故障定位
--------------------------------------------------------------------------------
Q1 双击 bat 或运行 ps1 报「无法读取本机端口监听表 … 拒绝访问」
   入口为避免把"查询失败"误判成"没监听"而硬报错。请在允许端口查询的会话里运行（普通用户桌面）；
   Codex/监督者在受限沙箱里会看到这条。
Q2 报「无法确认 18930 上这个后端是 Demo 实例 …」
   说明该端口上不是由本入口启动的后端（例如手工 uvicorn 或旧进程）。请让监督者**按同一个库**
   用 启动标准演示.ps1 重启；入口不会结束未知进程。
Q3 窗口起不来 / 一闪而过
   看 <库目录>\backend-*.err.log、frontend-*.err.log、electron-desktop.err.log；
   本包已包含「中文路径下 electron 需从 ASCII 缓存目录启动」的处理，缓存位置
   %LOCALAPPDATA%\TripCraft\desktop-runtime\<version>（仅缺失/版本不匹配时复制一次）。
Q4 消息中心里的待接单不是黄先生（例如「客户 K」）
   这台后端不是演示实例：普通 bat/`-Mode Normal` 就是随机游客。请用 启动标准演示.ps1 起演示模式。
Q5 待接单里没有黄先生、且启动无误
   确认是演示模式（DEMO_TOURIST=on）；旧进程可能只有 offline 没有该开关 → 按同一个库重启。
Q6 学习做久了会不会丢单
   不会：演示实例里未接单的固定单可续期；普通实例仍按原竞争规则（超时会判「已派他人」）。
Q7 评分页「待复核」为空
   先点「生成本单评分」；本案例置信度 0.6 低于阈值 0.7 → 11 条会全部进入待复核（校准基线未建立时
   不自动写画像）。逐条点「采纳」后 /profile 刷新可见。
Q8 前端改了没生效
   包内 dist 是构建产物；开发用 `cd frontend; npm run dev` 或 `npm run build` 重新构建。
Q9 真实模型模式跑不起来
   需要自备密钥（变量名见 _交接文档\配置示例\环境变量示例.txt：DEEPSEEK_API_KEY /
   LLM_BASE_URL / LLM_MODEL）。**离线固定案例不需要密钥。** 真实模型档未在本包验证。
Q10 端口被占用
   入口会报错退出，不会结束占用者；换端口需改 scripts\desktop_launch.ps1 里的两个端口常量
   （同时改前端 VITE_API_PORT 由脚本传入，无需手改）。
