3. 启动（唯一入口：桌面版）

两条入口共用一份实现 `scripts\desktop_launch.ps1`：
· 普通（默认：随机游客 + 真实模型链路）：双击 司南礼客桌面版.bat → `-Mode Normal`
  （后端 18020 / 前端 5190 / 库 .dsh-run\normal\preview.sqlite / 独立桌面会话）
· 内部演示（工作人员）：启动标准演示.ps1 → `-Mode Demo`
  （后端 18930 / 前端 15191 / 库 .dsh-run\codex-review\preview.sqlite，
   启动期声明 TRIPCRAFT_SCENARIO_MODE=offline + TRIPCRAFT_DEMO_TOURIST=on）

复用规则：只有运行目录里的 `instance.json` 与**真实进程身份**一致（mode / port / pid / 创建时间 /
库 / 演示开关）才复用；读不到端口表或身份不一致就**直接报错**，由监督者按同一个库重启该后端
（不结束未知进程，也没有「未验证也继续」的开关）。`instance.json` 只在**本次新启动**后端时写入；
手工 uvicorn 起的后端没有 marker，本入口会拒绝复用并提示用本入口启动。
----------------------------------------------------------------
  · 普通模式（默认；随机游客 + 真实模型链路）：双击仓库根 **司南礼客桌面版.bat**
    → `scripts\desktop_launch.ps1 -Mode Normal`（后端 18020 / 前端 5190 /
    库 .dsh-run\normal\preview.sqlite / 独立桌面会话）。**这条入口不做任何替换。**
  · 演示模式（工作人员用）：运行 **启动标准演示.ps1**
    → `scripts\desktop_launch.ps1 -Mode Demo`（后端 18930 / 前端 15191 /
    库 .dsh-run\codex-review\preview.sqlite）。**只有这条入口把随机游客替换成固定黄先生。**

两条入口都会用仓库内 Electron 桌面壳打开**独立应用窗口**（不是浏览器标签页）：
· 窗口加载本模式前端（普通 5190 / 演示 15191，同一份前端代码），API 走同源 /api 代理 → 本模式后端
· 各自一份桌面 profile：单实例锁互不干扰（不会把普通启动带回演示窗口）
· 第二次启动只聚焦已有窗口；关闭窗口**不会**结束后台服务

固定（演示模式）：前端 http://127.0.0.1:15191 · 后端 127.0.0.1:18930 ·
库 .dsh-run\codex-review\preview.sqlite（不清库） · 后端离线演示
（TRIPCRAFT_SCENARIO_MODE=offline + **TRIPCRAFT_DEMO_TOURIST=on** + TRIPCRAFT_BOOTSTRAP_ORDERS=1）；
端口已就绪则复用、被他人占用则报错退出，**不停止任何他人进程**、不重启 DSH。
请勿再用 TEMP 临时库或 scripts\start.ps1 等其它方式启动（会连到另一份数据）。
兼容（原网页入口，仅排障用）：在 启动标准演示.ps1 后加 -WebOnly，只打印网页地址、不开窗口。
若 /demo 显示「实时模型」：**停止演示**并确认 18930 上是由该入口启动的本项目离线实例——
该入口对已就绪端口只复用、不会把模式切回离线，重跑脚本并不能解决。

3b. 演示时游客是怎么被替换的（现场流程）
----------------------------------------------------------------
· 只有**显式内部演示实例**才会替换：后台启动开关 TRIPCRAFT_DEMO_TOURIST=on
  （+ TRIPCRAFT_SCENARIO_MODE=offline）。普通实例与正常双击入口一律不设该开关。
· 替换发生在服务端的**两个入口**：注册初始化（bootstrap）与主动派单
  （POST /practice/dispatch/generate）；公开 UI 不再有导入页，也不需要先「导入标准案例」。
· 现场就是普通流程：注册 → 12 题初测 → C6.1 学习 → 消息中心抢单（黄先生那单）→ 首呼 →
  四份文档 → 行中 → 行后。学习讲久了也不会丢单：演示实例的固定单在未接单时可续期，
  已抢单/已完成不回退；普通随机实例的竞争规则保持原样。
· 示例来源口径：演示实例内**任何用户名**注册的账号都按示例来源记账（kind=demo），不混进真实
  训练统计；固定资料与 demo_data / scenario_id 标记保留在服务端。
· 替换失败时**如实报错**（不静默退回随机客人），账号本身照常建好、数据保留。
· 普通实例不得被公开场景入口切走：/scenario 的导入 / 重置 / 校准 / 模式开关在普通实例一律拒绝
  （403；模式开关为 409，须启动期声明）。
