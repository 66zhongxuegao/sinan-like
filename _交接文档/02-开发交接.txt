TripCraft 司南礼客 · 02 开发交接（架构 / 模块 / 重要变更 / 已验与未验边界）
================================================================================
上游文档：docs\（PRD、开发计划、DECISIONS、携程改版说明、标准案例演示指南等文本）；
根目录 README-历史*.md 是旧版说明（免注册、旧隧道、13 步旧 UI），**不要当现行说明**。

--------------------------------------------------------------------------------
1. 技术栈与目录
--------------------------------------------------------------------------------
· 后端：Python 3.11+ / FastAPI / SQLite（自研 store 层）+ 确定性离线 provider（演示实例用）
· 前端：Vue 3 + TypeScript + Pinia + Element Plus + Vite；桌面壳：Electron（frontend/electron/main.cjs）
· 目录：
    tripcraft\api\            路由装配（app.py 汇总 ROUTER_MODULES）与各域路由器
    tripcraft\api\routers\    auth / practice / scenario / growth / deliverables / workbench 等
    tripcraft\services\       业务服务：practice_service（订单/派单/阶段）、scenario_service、
                              deliverable_service、plan_service、thread_service、tools_service 等
    tripcraft\contracts\      冻结契约：stages.py（六阶段）、deliverables(_spec).py、skill_points.py、
                              enums.py、rubric 等
    tripcraft\agents\         Agent：scenario（固定案例 spec 与确定性响应）、profiler、scorer 等
    tripcraft\storage\        数据库与 store（表结构、迁移、查询）
    data\scenario\            固定案例（standard_case.json）与知识/评分锚点数据
    frontend\src\views\       页面（vbooking / practice / learn / profile 等）
    frontend\src\demo\        /demo 内部排查页的数据访问层（scenarioApi/http/guide）
    frontend\electron\        桌面壳主进程（窗口、单实例锁、userData、开窗前置校验）
    scripts\                  启动（desktop_launch.ps1、desktop_selfcheck.cjs）与验收脚本
    tests\                    pytest 用例（隔离库，不碰真实历史库）

2. 六阶段状态机（现行口径，唯一来源 tripcraft\contracts\stages.py）
--------------------------------------------------------------------------------
pre1_requirement（需求确认单）→ pre2_plan（行程方案+客户确认）→ pre3_quote（分项报价+合规闸门）
→ pre4_notice（合同与保险、出团通知书）→ on_trip（行中事件）→ post_trip（结算/回访/评分/画像）
· 阶段与门槛由服务端投影（journey）：`GET /practice/orders/{id}/journey|gates`；
  前端不自己写动作表。
· 内部步骤 S0–S12 与六阶段映射见 stages.py；本包 docs\携程改版说明.txt 有背景。

3. 身份与权限（security v2）
--------------------------------------------------------------------------------
· 认证**始终强制**（没有 TRIPCRAFT_AUTH=off 旁路）；会话在服务端，HttpOnly cookie + Bearer token。
· 越权统一 403/404：own_order / require_self；公开路径白名单在 security.py。
· 账号 kind：username 以 demo- 前缀注册 → kind=demo（示例来源）；其它 → real。
  **在内部演示实例里，任何用户名注册都按示例来源记账**（避免混进真实统计）。
· 登录页 / 注册页 / 主导航 / 首页**没有**标准案例入口；内部排查页 /demo 只在演示实例可访问，
  普通实例访问会回首页。

4. 两种启动模式与「演示游客替换」（本次重要变更）
--------------------------------------------------------------------------------
· 单实现：scripts\desktop_launch.ps1
    -Mode Normal（默认）→ 18020/5190、.dsh-run\normal\preview.sqlite、无演示开关
    -Mode Demo          → 18930/15191、.dsh-run\codex-review\preview.sqlite、
                           TRIPCRAFT_SCENARIO_MODE=offline + TRIPCRAFT_DEMO_TOURIST=on +
                           TRIPCRAFT_BOOTSTRAP_ORDERS=1
    两个薄入口：司南礼客桌面版.bat（Normal）/ 启动标准演示.ps1（Demo，命名参数转发）
· 替换发生在**服务端两个入口**（不依赖账号名 / localStorage / 公开 UI）：
    - 注册初始化：tripcraft\api\routers\auth.py::_bootstrap_new_account → 固定案例单；
    - 主动派单：tripcraft\api\routers\practice.py::POST /practice/dispatch/generate。
    实现：tripcraft\services\scenario_service.py::demo_instance() / demo_replacement()（幂等复用，
    不重复建单；失败**如实报错**，绝不静默退回随机游客）。
· 演示时效：maybe_renew_demo_window() + practice_service 的两个钩子（dispatch_info / available_orders）
  —— 演示实例里**未接单**的固定单可续期（学习等待不丢单）；已抢单/已完成不回退；
  普通实例的竞争规则（15 分钟窗口、竞争者 80%–93% 时点判「已派他人」）**保持原样**。
· 普通实例防误切：/scenario 的导入 / 重置 / 校准在非演示实例一律 403；provider/offline|live 返回 409
  （必须启动期声明）；/scenario/status 暴露 demo_instance 对象供前端门禁与运维核对。
· 启动脚本身份校验：运行目录 instance.json + 真实进程（mode/port/pid/创建时间/库/演示开关）一致才复用；
  端口/进程查询失败**硬报错**（不把"查询失败"当"没监听"）；新启动用 Start-Process -PassThru 的 PID
  核对确实在监听；创建时间用带时区的 'o' 格式。**不要删除 instance.json。**

--------------------------------------------------------------------------------

未验 / 限制

· 真实模型（live）档未在本包验证（需自备 DEEPSEEK_API_KEY / LLM_BASE_URL / LLM_MODEL）。
· **换机环境未实机验收**：适配器/恢复器只做了静态与逻辑校验，未在另一台干净机器上实际安装。
· 历史开发辅助：根目录 `一键启动.bat` / `停止服务.bat` 是旧 web 开发/停服流程，非桌面入口。
· 真实模型（live）档只在有密钥时有意义；离线固定案例不依赖外部模型。
· 本包内的库快照只含成品账号与订单 9000000000000009（其它账号未纳入；sessions 已清空）。

8. 接手时最容易踩的坑
--------------------------------------------------------------------------------
1) 别把普通 bat 当演示入口（普通=随机游客）；演示必须用 启动标准演示.ps1。
2) 换机先跑 _交接文档\首次安装与适配.ps1（脚本里的 python/node 路径是打包机的）。
3) 演示实例的后端必须**由入口启动**（手工 uvicorn 不会有 instance.json，入口会拒绝复用）。
4) 不要给"未验证也继续"开旁路：入口在身份无法核对时就是报错，这是设计。
5) 改固定案例只改 data\scenario\standard_case.json；改完跑 acceptance_standard_case 看 diges/断言。
6) 不要把演示固定数据做成真实统计：演示实例内注册一律 kind=demo，固定单带 demo_data/scenario_id。
7) 前端样式令牌在 frontend\src\styles\tokens.scss（与 global.scss 一起，必须随源码带走，
   它不是凭证文件）。
