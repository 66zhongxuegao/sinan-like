# 首呼客户角色边界修复（2026-10-17）

## 问题与定位

截图中的客户先表达自己的旅行需求，随后说“你希望我们安排哪些城市呢”“你比较想去哪几个”，接过了定制师采集需求的工作。

当前语音入口使用 `voice/bridge.py → services/customer_context.build_customer_system → agents/customer.build_customer_system` 的共用提示词。对话中的客户映射为 assistant、定制师映射为 user，映射正确。

原有规则要求“始终是客户”“不用客服口吻”，也限制了客户反问自己的已知人数、预算等事实，但缺少代词指向、双方职责和听不清时的明确行为。共用回复检查原先检查事实、数字和语言，未识别角色越权。因此不含事实冲突的服务方问句会通过检查，并作为客户历史重新进入上下文。截图的异常语音转写可能促成了这次偏离，具体模型推断过程无法从记录确定。

## 修改

- 新增 `contracts/customer_role.py`，集中定义客户角色边界：我/我们指游客及同行者，你/您指定制师；客户表达需求、回应追问、请求建议，定制师负责需求调查与方案服务。
- 明确听不清、无法理解或只有零碎语气词时简短请求重说，等待对方继续。
- 规则接入实际使用的共用提示词，同时覆盖旧语音提示词构建器。例句不固定目的地，避免误带入其他订单。
- 共用 `customer_card.check_reply` 增加明确服务方句式检查，覆盖本次两句。文字、聊天、文档反馈沿用一次纠正重试；实时语音沿用播放前检查与纠正重试，再次失败时用事实卡模板显示文字。
- 过滤模型上下文中命中越权规则的旧客户台词，保留数据库原始通话记录和定制师原话。

普通客户询问“你建议我去哪”“有哪些地方适合我们”“你推荐的路线能控制在我们的预算内吗”继续允许。规则针对明确句式，无法穷尽所有语言和角色偏离表达。

## 生效与验证范围

结束当前通话，运行项目根目录的 `重启司南礼客.bat`，再发起新通话。已经建立的实时模型会话保留其原始上下文，应重新建立。
