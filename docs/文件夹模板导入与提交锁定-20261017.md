# 文件夹模板导入与提交锁定

2026-10-17（完整模拟资料补齐版）

## 使用

文件夹工作台在“导出 PDF”左侧新增“导入模板”。点击一次，为当前订单尚未提交的八类文件批量保存草稿。导入不弹确认框，不投递文件，不触发客户回复，也不登记确认、证据或阶段完成动作。提交仍由用户逐份手动点击。

按用户本次授权，一键导入补齐当前订单八类待填写文件的全部字段。优先沿用本单共用客户事实卡、已提交文件、完整行程和可用报价；未知项用订单号稳定生成模拟资料。人数、日期、预算、住宿和特殊需求保持同源。新增客户事实写入共用事实卡，标记为模拟补充，后续公开展示、文本及语音角色沿用。已有隐藏设定使用原值。

缺少的合同号、保单号、签署日期、报价金额、集合地点、模拟联络号和回访结果均补齐。合同、定金及结清状态按完整模拟案例填写；自由说明明确标注模拟来源。导入只保存这些字段，用户手动提交后才按现有流程登记动作。模拟编号采用 SIM 前缀，避免生成真实手机号或假冒真实商业凭证。

八份文件共用出行人数、日期、逐日行程、销售总价、采购成本、定金和毛利。金额按分分配并交叉核对，行程支持一日游。缺失草稿项会补全，不合格占位及金额关系会修复；已有可用补充说明保留。

保存前逐份执行必填、字段算术、确定性规则及已配置的语义合规预检，全部通过才提示可提交。语义校验明确识别模拟资料，继续拦截饮食、身份、安全和文化冲突。预检结果及内容/订单事实签名保存在服务端；手动提交的内容及事实未变时复用当次合格结果，减少重复模型判定差异。修改内容或订单事实后重新校验，字段和金额始终重新检查。

草稿和预检记录保存到按订单及文件区分的 `deliverable_draft` 表，切换文件、刷新或重新登录后仍可读取。正式提交记录优先于草稿，已提交文件不会被一键导入覆盖。

## 提交状态

成功投递后，“提交并投递”变为灰色“已提交并投递”，表单锁定。切换至其他未提交文件可继续填写和投递，PDF 仍可导出。校验拦截、网络错误未确认成功时保留修改与重试入口。

工作台提交请求携带 `submit_once=true`。服务端按订单和文件串行检查已提交状态；重复请求读取已有回执，不再次投递、登记证据或推进门槛。其他方案版本入口继续保留原有版本更新语义。

## 检查与生效

Python 静态检查、前端类型检查与生产构建通过。完整模板、既有交付物和拦截网回归共 40 项通过；使用内存库验证缺失资料、国内/台湾/沙特、一日游、逐份手动提交、重复提交、内容改动后重新校验及不合格预检不保存。

另使用实际订单库的内存副本，对 33 个订单批量导入并逐份提交 251 份待填文件，均未被拦截；不对真实订单自动导入或投递。离线验证不调用真实模型通话。
