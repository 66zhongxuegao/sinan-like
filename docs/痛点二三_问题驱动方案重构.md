# 痛点二、痛点三：问题驱动型技术方案重构

> 日期：2026-11-03  
> 目标：不再从现有页面和现有功能出发，而是从赛题真实问题出发，反推必须采用的技术方案。

---

## 一、先重构问题，不先想功能

赛题不是问“怎样做一个生成资源的系统”，而是在问：

> 当学习者状态不可直接观测、专业知识又不能出错时，如何让多智能体持续做出“教什么、怎么教、生成什么、是否可信”的决策？

因此，本项目的本质不是：

- RAG；
- 多智能体聊天；
- 个性化内容生成；
- 普通知识图谱。

而是一个**高风险、部分可观测环境下的教学决策系统**。

可以抽象成一条决策链：

```text
隐藏的学员状态与知识真值
        ↓
多源观察：测验、对话、任务、交付物
        ↓
更新信念：掌握度、误解、不确定性、风险
        ↓
选择行动：问什么、讲什么、练什么、是否拒答
        ↓
观察结果
        ↓
再次更新信念
```

这正对应赛题的：

- 学情画像；
- 个性化生成；
- 多智能体协同；
- 幻觉防控与知识溯源；
- 动态反馈。

---

## 二、痛点二重构：学情可适配

### 1. 更痛的痛点

原表达：

> 学情层不适配——统一课程与题库，无法补齐不同背景学员的能力缺口。

问题仍然偏一般化。真正让培训走不通的是：

- 学员真实能力是隐藏的；
- 一次测验只能得到一个低维分数；
- 分数无法区分“不会”“误解”“遗忘”“前置缺口”“会做但不会迁移”；
- 错误路径一旦选定，学员会在错误技能上持续训练；
- 这种偏差往往要等真实接单才暴露，而这时已经产生业务损失。

因此更准确的问题是：

> **学情状态不可观测——一次测验只给分数，误解与前置缺口被隐藏。**  
> **路径一旦选错，训练越久偏差越大，直到真实接单才暴露。**

### 2. 为什么现有方法解决不了

普通的“画像 + 推荐”方案仍然有三个硬伤：

1. **只测结果，不测原因**：答错只能说明答案错，不能判断是概念误解、前置缺失还是粗心。
2. **只匹配资源，不选择行动**：推荐下一份资料，不等于决定“该追问、降维解释、换案例、做练习还是进阶”。
3. **只按标签推路径，不做因果预测**：学员被贴上“基础弱”后得到简单资源，但没有人知道下一步动作会让掌握概率提升多少。

所以，个性化不能停留在“画像标签 → 模板分支”。

### 3. 技术方案一：主动信念诊断

关键词：

- Active Bayesian Experimental Design
- Expected Information Gain
- Adaptive Diagnostic Querying

核心思想：

> 不是把一整套题做完，而是每一题都选择“最能减少当前学员状态不确定性”的观察。

具体实现：

- 维护每个技能点的掌握概率；
- 维护误解、提示依赖、遗忘和迁移状态；
- 对每个候选诊断题预估：
  - 答对 / 答错后对学员信念分布的更新幅度；
  - 对后续教学决策的价值；
- 选择信息增益最大的下一题或下一个对话追问；
- 当信念足够确定时提前停止诊断。

可落地性：

- 第一版可使用 LLM 给出每题的条件正确率估计；
- 结合简化 BKT / Bayesian update 更新掌握概率；
- 信息增益用候选分布熵差或置信区间缩短量近似；
- 不需要一开始训练强化学习模型。

技术价值：

- 诊断题量更少；
- 能区分“不会”和“误解”；
- 为下一步教学选择提供概率依据。

### 4. 技术方案二：双状态学习者孪生

关键词：

- Dual-State Learner Twin
- Soft-Evidence Bayesian Knowledge Tracing
- Misconception State

学习者状态不是一张雷达图，而是两层状态：

#### 第一层：知识状态

- 每个技能点的掌握概率；
- 掌握不确定性；
- 遗忘趋势；
- 迁移能力。

#### 第二层：误解状态

- 常见错误类型；
- 错误发生在什么任务和条件下；
- 提示依赖程度；
- 是否会把一个知识点误用到其他场景。

LLM 作为观察函数，将答题、对话和交付物转化为连续证据，而不是把答错简单变成 0 分。

### 5. 技术方案三：约束课程策略

关键词：

- ZPD-Constrained Curriculum Policy
- Prerequisite Graph Planning
- Counterfactual Rollout

每一步教学动作由约束规划器选择：

- 先修知识是否满足；
- 资源成功概率是否落在最近发展区；
- 是否能覆盖最弱技能；
- 认知负荷是否可接受；
- 训练成本是否可控。

动作空间不是只有“下一份资料”，而是：

- 追问；
- 降维解释；
- 换案例；
- 做练习；
- 进入实战；
- 提高难度；
- 回退前置知识。

第一版可以不做完整强化学习，而采用：

- 知识图约束的候选动作生成；
- LLM 估计候选动作的预期掌握增益；
- 规则 + beam search 选择动作；
- 记录实际结果，后续再升级为 contextual bandit。

### 6. 技术方案的赛题呼应

| 赛题要求 | 对应技术 |
|---|---|
| 学习者先验知识画像 | Active Belief Diagnosis |
| 个性化资源生成 | Dual-State Learner Twin 驱动 |
| 动态难度与路径 | ZPD-Constrained Curriculum Policy |
| 交互反馈与更新 | 贝叶斯信念更新 |
| 多智能体协同决策 | 诊断、规划、生成、评估角色分工 |

### 7. 可展示效果

- 画像—资源适配准确率≥90%；
- 诊断题量下降；
- 学习增益高于统一课程；
- 路径调整能解释“为什么下一步这样做”。

## 三、痛点三重构：风险可拦截

### 1. 更痛的痛点

原表达：

> 合规层不可试错——历史文化、宗教饮食与安全内容一旦出现幻觉，直接影响交付。

需要更具体地指出“为什么必须解决”：

- 一条历史叙事错误会引发投诉；
- 一条宗教饮食错误会影响整个行程；
- 一条安全建议错误会造成真实人身风险；
- 普通 RAG 只找相似段落，不能证明一句具体结论是否有依据；
- 模型即使证据不足也会继续输出，缺少“拒答”机制。

因此更准确的问题是：

> **专业结论不可证明——生成内容看似流畅，却无法逐条证明依据。**  
> **在文化合规场景，一次无法回溯的错误就足以击穿整单交付。**

### 2. 为什么普通 RAG 不够

普通 RAG 做的是：

```text
问题 → 相似段召回 → 拼接上下文 → LLM 回答
```

它不能保证：

- 每个事实 claim 都能被证据支持；
- 检索到的是相关段落，但不是充分证明；
- 多个来源冲突时谁优先；
- 模型在证据不足时是否应该拒答；
- 高风险内容是否应该直接转人工。

因此关键不是“更多检索”，而是**逐 claim 可验证、可弃权、可审计**。

### 3. 技术方案一：本体约束 Agentic RAG

关键词：

- Ontology-Grounded Agentic RAG
- Entity / Relation Constraints
- Evidence Graph

实现：

- 对历史文化、宗教饮食、场所安全等内容建本体；
- 把实体、关系和风险规则显式建模；
- 检索时不仅做相似度匹配，还检查：
  - 实体是否存在；
  - 关系是否合法；
  - 场景是否适用；
  - 是否有冲突规则；
- 让检索结果与 ontology observation 一起进入证据链。

### 4. 技术方案二：Claim–Evidence 共形校验

关键词：

- Claim Decomposition
- NLI Verification
- Conformal Factuality
- Selective Prediction

实现：

1. 将生成内容拆成多个可验证 Claim；
2. 每个 Claim 检索证据；
3. 使用独立 NLI / LLM verifier 判断 entailment 与 contradiction；
4. 在验证集上校准“保留阈值”；
5. 只保留证据充分的 Claim；
6. 证据不足则拒答或转人工。

这不是“让模型自检”，而是：

- 生成与审核分离；
- Claim 级验证；
- 可控的拒答率；
- 可报告的 support 指标。

### 5. 技术方案三：风险闸门与人审

关键词：

- Risk Gate
- Hard Veto
- Abstain
- Human-in-the-Loop

风险分为：

- 红色：涉政、历史叙事、宗教禁忌、人身安全；
- 黄色：来源冲突、案例不足、场景不确定；
- 绿色：有稳定知识依据的常规内容。

处理策略：

- 红色：一票否决或强制人工；
- 黄色：双 Agent 交叉验证；
- 绿色：自动放行；
- 证据不足：Abstain，不输出确定结论。

### 6. 技术方案的赛题呼应

| 赛题要求 | 对应技术 |
|---|---|
| 多智能体协同 | 生成、拆分、本体检索、NLI、风险裁决角色分工 |
| 幻觉防控 | Claim-level verification |
| 知识溯源 | Evidence graph + support level |
| 高保真 | 本体约束 + 风险规则 |
| 决策闭环 | Approve / Veto / Abstain / Human review |

### 7. 可展示效果

- 幻觉率<5%；
- 高风险测试集拦截率100%；
- 证据覆盖率≥95%；
- 高风险内容人工复核率可量化；
- 每条通过审核的 Claim 都有证据来源。

## 四、两页共同的技术主线

两页不是两个独立模块，而是同一个技术体系的两侧：

### 左侧：学员状态决策

```text
观察 → 信念更新 → 行动选择 → 新观察
```

解决“下一步该教什么”。

### 右侧：知识验证决策

```text
生成 → Claim 拆分 → 证据校验 → 风险裁决
```

解决“这一步生成的内容能不能信”。

两者共同构成：

> **高风险、部分可观测条件下，多智能体驱动的教学决策闭环。**
