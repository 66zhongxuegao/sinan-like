# 初始测评入口修复

2026-10-17

## 问题与证据

账号 `1234` 未完成初始测评，但已有 5 条实战评分。只读检查普通实例的 `.dsh-run/normal/preview.sqlite`：该账号有 0 条能力记录、0 条初始快照、0 条画像报告。

原入口和提交接口均使用 `has_profile_data()` 判断是否允许初始测评。该判断包含做题与实战评分，因此先参加实战的账号会被关闭测评入口。账号 `123` 的另一份已完成测评仍保存在其本人名下。

## 修复

- 新增 `Store.has_initial_assessment()`，按持久化初始快照或初始报告判断是否完成测评；兼容没有快照的历史初始报告。
- `/profiles/{user_id}/intake` 与 `/profile/assessment` 共用新判定。未完成初始测评的账号可补做一次，完成后仍拒绝重复提交。
- 补做时仅初始化缺失的能力项，保留已有学习及实战能力值；测评分数另存初始快照。
- 学情画像页顶部显示当前账号及初始测评入口；首页按钮明确为“开始初始测评”。
- 题目页区分加载中、读取失败与已完成测评，读取失败可重试。
- 当前能力尚未评估时，禁用“更新画像”按钮，先引导完成初始测评。

此次未修改账号、历史记录或数据库文件。

## 检查与使用

两个 Python 修改文件通过 AST 静态语法解析；前端 `vue-tsc --noEmit` 通过。按用户此前要求，未运行测试、未启动软件、未调用模型。

结束当前通话后运行项目根目录的 `重启司南礼客.bat`，登录 `1234`，在首页或“学情画像”页选择“开始初始测评”。
