## 一、重新理解赛题

赛题不是要求“做一个旅游应用”，而是在考：

> 如何面向真实垂直岗位，构建一套能够理解学习者、生成专业资源、控制幻觉、接受反馈并持续更新的领域知识个性化生成与多智能体协同决策系统。

赛题的主线可以压成四项：

1. 真实垂直技能场景；
2. 基于学情的个性化资源生成；
3. 多智能体可信协同与幻觉控制；
4. 可反馈、可验证、可部署、可迁移的闭环。

赛题给出的 “多智能体、个性化、RAG、审核 Agent、动态反馈” 是中间答案。我们要补全的是：它们分别解决了什么真实业务问题，以及为什么非这样不可。

## 二、项目故事总纲

建议采用四痛点结构。

> 入境游定制师不是在卖路线，而是在卖对整趟旅程负责的交付能力。  
> 培训市场存在四个真实痛点：经验难复制、学情难适配、高风险内容不能试错、会答题不等于会接单。  
> 这四个痛点正好对应赛题的领域知识生成、学情画像、多智能体可信协同和动态闭环要求。  
> 司南礼客用“三图双环”的技术架构，把专家经验、学员状态和证据链组织成可运行的训练系统，并用可量化实验证明它比普通大模型和静态培训更有效。

一句话技术定位：

> 面向高风险职业技能培训的“学习者数字孪生 + 知识图谱 + 证据约束多智能体”闭环系统。

## 四、痛点一：经验难复制

### 1. 业务痛点

入境游定制师的核心能力不是背景点知识，而是同时判断：

- 游客真实需求；
- 行程节奏；
- 资源可用性；
- 报价与利润；
- 跨文化沟通；
- 行中变更和安全风险；
- 谁对最终结果负责。

这些判断高度非标，主要存在于成熟定制师经验中。传统课程只能讲知识点，师傅带教无法规模化。

### 2. 赛题考点

- 领域知识库；
- 个性化资源生成；
- 至少三种资源形态；
- 知识覆盖与专业质量；
- 知识溯源。

### 3. 技术方案

#### 技术点 A：领域知识图谱与技能本体

构建四类节点：

- 知识概念；
- 技能点；
- 业务任务；
- 证据/规范来源。

构建五类边：

- 前置依赖；
- 属于任务；
- 需要证据；
- 易混淆；
- 高风险关联。

这样，知识不是一段段文档，而是可规划、可覆盖、可审计的结构。

#### 技术点 B：符号化任务模型 + LLM 生成

参考前沿的神经—符号混合思路，将 13 步业务流程和 Rubric 作为显式结构约束，LLM 只负责在结构边界内生成讲解、案例、追问和反馈，不能自由发明流程。

这解决两个问题：

- 普通大模型会生成“看起来合理但不符合行业流程”的内容；
- 纯提示词系统难以保证每一步交付物和门控条件。

#### 技术点 C：混合检索与 GraphRAG

- BM25 负责术语、编号、SOP 的精确召回；
- 稠密向量负责语义召回；
- cross-encoder 重排；
- 知识图谱负责前置关系和全局结构；
- GraphRAG 用于跨文档、跨任务的全局知识组织；
- 每条资源绑定知识点、证据片段和知识库版本。

### 4. 成效指标

- 核心知识点覆盖率≥90%；
- 专家对资源专业性评分≥4.2/5；
- 资源结构完整性≥90%；
- 证据引用覆盖率≥95%；
- 生成一份个性化资源的耗时低于人工制作的某个明确基线。

### 5. 参考研究

- Ivy：符号任务模型约束 LLM，提升“怎么做、为什么”的程序性解释结构质量（arXiv:2511.20942）。
- GraphRAG：用图索引和社区摘要处理全局知识和跨文档问题（arXiv:2404.16130）。
- GraphMASAL：动态知识图谱 + Diagnostician/Planner/Tutor 三类 Agent + 图约束规划（arXiv:2511.11035）。

## 五、痛点二：学情难适配

### 1. 业务痛点

文旅专业、计算机背景、语言跨文化背景的学员，薄弱点完全不同：

- 语言强的可能不会做资源核验；
- 文旅强的可能不会处理数据与系统；
- 技术强的可能不懂宗教饮食和文化禁忌；
- 新人的真正问题是“不知道自己不知道什么”。

统一课程无法解决这个问题。

### 2. 赛题考点

- 学习者先验知识画像；
- 知识盲区定位；
- 资源难度匹配曲线；
- 学习路径规划；
- 基于交互反馈的动态更新。

### 3. 技术方案

#### 技术点 A：学习者数字孪生

学习者状态不是一张雷达图，而是一个持续更新的概率状态：

- 每个技能点的掌握概率；
- 掌握不确定性；
- 常见误解类型；
- 任务独立性（是否需要提示）；
- 证据记录；
- 最近遗忘趋势。

#### 技术点 B：软证据 Bayesian Knowledge Tracing

参考 CoLearn 的思路，将 LLM 作为连续观测函数，每次答题、对话、交付物和提示使用都更新掌握概率，而不是把答错简单记成 0 分。

#### 技术点 C：误解图谱与“未知的未知”

参考 RPKT 和 PersonaPath，不预设所有路径都从固定知识图谱开始，而是递归追溯前置概念，定位学员真实知识边界，并对最薄弱的前置节点生成补练。

#### 技术点 D：ZPD 约束学习路径规划

每个资源都有：

- 前置技能；
- 难度等级；
- 认知负荷；
- 目标技能；
- 证据要求。

规划时同时优化：

- 弱项覆盖；
- 前置依赖满足；
- 预计成功率处于最近发展区；
- 学习成本；
- 资源多样性；
- 与真实任务的相关性。

这不是让 LLM 随意推荐“下一课”，而是带约束的图规划问题。

### 4. 成效指标

- 画像—资源难度适配准确率≥85%；
- 同一知识点对三类画像生成明显不同的资源与路径；
- 学习增益显著高于统一课程；
- 延迟后测保持率高于基线；
- 路径完成率和学习成本均有改善。

### 5. 参考研究

- CoLearn：软证据 BKT + 误解记忆 + 证据可视化；个性化题目在盲测中被偏好 68%—69%（arXiv:2609.21154）。
- GraphMASAL：动态知识图谱与多源多目标学习路径规划（arXiv:2511.11035）。
- PersonaPath：面向知识点的个性化路径规划 benchmark；最强 LLM 最终通过率仅 29.5%，说明自由生成路径远不够（arXiv:2609.18861）。
- RPKT：递归前置知识追踪，解决“不知道自己不知道”（arXiv:2508.11892）。

## 六、痛点三：高风险内容不能试错

### 1. 业务痛点

旅游培训不是普通问答。历史叙事、宗教习俗、饮食禁忌、敏感场所、安全应急一旦出错，代价不是一道题答错，而是投诉、舆情和人身风险。

单模型同时追求个性化和专业性会发生冲突：

- 放开限制去迎合学情，专业内容可能失真；
- 严格限制确保准确，资源又容易模板化。

### 2. 赛题考点

- 至少三个职责明确的 Agent；
- 分析—生成—校验—决策闭环；
- 多智能体辩论和交叉验证；
- 知识溯源；
- 高保真、可控生成。

### 3. 技术方案

#### 技术点 A：生成与审核分离

- 学情诊断 Agent：判断学员弱项；
- 教学规划 Agent：选择讲解、案例、练习或挑战；
- 资源生成 Agent：生成候选内容；
- 事实核验 Agent：逐条检查 claim 是否有证据支持；
- 风险审核 Agent：检查文化、历史、安全和合规风险；
- 调度裁决 Agent：汇总意见、决定采纳、返工或转人工。

生成者不能给自己的内容打分。

#### 技术点 B：Claim-level evidence verification

把生成内容拆成可核验的事实主张：

- 每个 claim 绑定证据片段；
- 使用独立 NLI/LLM verifier 检查 entailment；
- 对无证据或证据不足的 claim 直接拒绝；
- 对冲突证据显式记录；
- 对高风险问题转人工。

这比“让同一个模型再检查一遍”更可靠。

#### 技术点 C：风险否决与反方代理

- 建立高风险知识规则库；
- 设置红黄绿风险等级；
- 设置专门的“反方审计 Agent”寻找反例、禁忌和文化冲突；
- 高风险内容必须命中审核知识；
- 争议案例进入人工复核队列。

#### 技术点 D：可信降级

参考 conformal factuality 的“宁可不答，不可乱答”思想：

- 证据不足时不生成确定结论；
- 改为追问、给出来源范围或请求人工；
- 记录 abstention 的原因。

### 4. 成效指标

- 专业知识幻觉率<5%；
- 证据支持率≥95%；
- 高风险红队案例拦截率100%；
- 风险规则命中准确率≥90%；
- 人工复核记录完整率100%。

### 5. 参考研究

- Multiagent Debate：多实例提出、辩论和收敛，能减少错误答案和幻觉（arXiv:2305.14325）。
- Self-RAG：模型学习检索、生成和自我批判（arXiv:2310.11511）。
- EduGuard：独立 verifier + 课程检索 + rubric 生成，报告幻觉率 4.9%（arXiv:2607.15738）。
- Conformal Factuality in Agentic RAG：用 claim-level 过滤提高支持率，但会降低回答覆盖，说明可靠性与可回答性需要权衡（arXiv:2610.34872）。
- Agreement Is Not Validity：多个 LLM 达成一致不等于诊断有效，仍需要独立人类证据和效度验证（arXiv:2610.08703）。

## 七、痛点四：会答题不等于会接单

### 1. 业务痛点

传统培训常用选择题、知识点问答或听课完成率衡量效果，但定制师真正需要交付的是：

- 需求确认单；
- 行程方案；
- 资源询价与报价；
- 合同与保险信息；
- 行前准备清单；
- 突发事件处理记录；
- 结算与复盘报告。

如果系统只验证“知道”，不验证“交付”，培训结果无法迁移到真实岗位。

### 2. 赛题考点

- 完整闭环；
- 交互反馈与动态决策；
- 资源生成和实际应用的结合；
- 系统可部署、可测试；
- 领域可迁移。

### 3. 技术方案

#### 技术点 A：符号化 13 步业务状态机

每一步定义：

- 系统输入；
- 学员动作；
- 交付物；
- 通过条件；
- 失败回退；
- 评分点；
- 证据记录。

LLM 只能在步骤边界内生成内容和反馈，不能替代流程门控。

#### 技术点 B：真实交付物驱动评估

从“答题是否正确”升级为：

- 交付物是否完整；
- 证据是否充分；
- 资源是否可兑现；
- 风险是否识别；
- 客户需求是否闭环；
- 是否能在未知场景迁移。

#### 技术点 C：多轮场景模拟与长时程评测

- 虚拟游客和资源方拥有独立状态；
- 场景导演逐步释放需求和事件；
- 通过多轮对话观察学员是否主动追问、识别风险、调整方案；
- 用长时程任务评估学习保持和迁移，而不是只看一次生成结果。

#### 技术点 D：真实反馈外环

真实订单和游客反馈：

```text
真实服务结果
  → 脱敏案例
  → 人工审核
  → 更新知识/规则/Rubric
  → 回归测试
  → 发布新版本
```

不宣称自动在线学习，保证每次更新可审计。

### 4. 成效指标

- 13 步任务通过率；
- 首次交付合格率；
- 未见过场景的迁移通过率；
- 延迟保持率；
- 专家对交付物的评分；
- 培训周期和师傅带教时长；
- 资源返工次数。

### 5. 参考研究

- EduClaw-Bench：30 天长时程、55 个场景，评估学习增益、响应性和帮助性；说明短对话 benchmark 无法代表长期教学效果（arXiv:2608.03206）。
- HACHIMI-II：用学习者历史建模行为，而不是让模型简单“扮演学生”（arXiv:2610.19654）。
- Agentic University：将目标、活动与分层评估连接，学习者参与多智能体组织（arXiv:2610.40492）。
- Do LLM Tutors Actually Teach?：强调不能只验证单个组件，要验证学习者状态推断、教学行动、学习增益和迁移之间的接口（arXiv:2610.15692）。

## 八、“三图双环”技术架构

建议把系统技术亮点收敛成一个清晰的架构：

### 三张图

1. **学习者状态图**：掌握概率、误解、证据、提示依赖、遗忘趋势。
2. **领域知识图**：技能、前置关系、任务、资源、规范、风险。
3. **证据图**：claim、来源、支持关系、冲突、审查结论、版本。

### 两个环

1. **内环：个性化学习闭环**  
   学习证据 → 状态更新 → 路径规划 → 资源生成 → 证据核验 → 交互评估 → 状态再更新。

2. **外环：真实服务演化闭环**  
   真实订单/反馈 → 脱敏与人工审核 → 案例入库 → 知识和规则更新 → 回归测试。

### 一个确定性编排器

- 决定调用哪些 Agent；
- 管理依赖和 Blackboard；
- 记录调用理由、耗时、证据和失败；
- 不允许 LLM 直接控制全部流程；
- 让多智能体既灵活又可审计。

### 与赛题的对应

| 技术亮点 | 赛题考点 | 项目中的实现 | 量化指标 |
|---|---|---|---|
| 学习者数字孪生 | 学情画像、动态反馈 | 软证据 BKT + 误解状态 + 证据记录 | 适配准确率≥85%；学习增益 |
| 知识图谱 + GraphRAG | 领域知识库、路径规划 | 技能图、前置边、混合检索、图规划 | 覆盖率≥90%；路径合法性 |
| 符号任务模型 + LLM | 垂直技能、完整闭环 | 13 步状态机、交付物门控、Rubric | 任务通过率；流程违规率 |
| 证据约束多智能体 | 多 Agent、幻觉控制、溯源 | 生成/核验/风险/裁决分离 | 幻觉率<5%；证据支持率 |
| 长时程场景仿真 | 交互反馈、动态决策 | 多轮游客/资源方/事件、延迟后测 | 迁移率；保持率 |
| 可审计决策面板 | 可视化报告、UX | Trace、证据图、路径解释 | 专家可解释性评分 |

## 九、实验设计

### 1. 测试集

- 3 类以上学习者画像；
- 1 个入境游领域知识切片；
- 50 个以上案例；
- 30 个常规业务案例；
- 20 个高风险幻觉和合规案例；
- 至少 10 个未见过场景用于迁移测试。

### 2. 对照组

建议至少四组：

- B0：通用大模型直接生成；
- B1：大模型 + 普通 RAG；
- B2：多 Agent，但没有符号任务模型或证据否决；
- B3：司南礼客完整方案。

如果条件允许，再加：

- B4：完整方案去掉学习者数字孪生，验证个性化增益；
- B5：完整方案去掉风险否决，验证风控增益。

### 3. 指标定义

- 幻觉率 = 错误或无依据事实 claim 数 / 全部可核查 claim 数；
- 证据支持率 = 有可验证来源支持的 claim 数 / 全部事实 claim 数；
- 知识点覆盖率 = 覆盖的目标技能点 / 应有技能点；
- 适配准确率 = 专家判定资源和难度匹配的样本数 / 总样本数；
- 学习增益 = 后测减前测；
- 延迟保持率 = 延迟后测 / 即时后测；
- 任务通过率 = 通过交付物门控的任务数 / 总任务数；
- 迁移通过率 = 未见场景任务通过率；
- 人工成本 = 师傅/专家的审核时间和重复答疑时间；
- 可信度 = 专家对证据链和决策理由的评分。

### 4. 结果呈现

每项技术至少对应一张图：

- 基线 vs 完整方案柱状图；
- 三类画像的路径差异图；
- 前后测学习增益图；
- 幻觉率和证据支持率对比图；
- 消融实验图；
- 延迟保持率曲线。

## 十一、当前最值得拿出来的技术亮点

### 亮点一：不是静态画像，而是可更新的学习者数字孪生

- 每个技能点有掌握概率和不确定性；
- 误解和提示依赖被显式记录；
- 每次交互都更新状态；
- 路径和资源由状态驱动，不是预设脚本。

### 亮点二：不是自由生成，而是符号任务模型约束生成

- 13 步业务流程、交付物和 Rubric 是硬约束；
- LLM 只做受控生成；
- 这样可以同时保证流程合规和表达个性化。

这是项目区别于普通 RAG 或多 Agent 聊天系统的核心技术差异。

### 亮点三：不是生成后自检，而是生成与核验分离

- 生成器不验证自己的结果；
- 独立 verifier 做 claim-level 证据检查；
- 风险 Agent 可以一票否决；
- 不足证据时允许拒答或转人工。

### 亮点四：不是刷题，而是用真实交付物评估能力

- 需求单、行程、报价、结算和复盘都是评分对象；
- 评估真实工作物，而不是只考选择题；
- 可以做未见场景迁移和延迟保持。

### 亮点五：不是一个行业黑盒，而是可迁移的领域包架构

- 领域知识包；
- 技能图谱包；
- 风险规则包；
- 评测包；
- 模型、语音、翻译和工具适配层。

## 十三、必须避免的表达

- “我们用了多智能体，所以一定比单模型好。”  
  必须用消融实验证明。
- “我们用了 RAG，所以没有幻觉。”  
  必须用 claim-level 证据和人工评测证明。
- “我们有画像，所以实现了个性化。”  
  必须证明画像改变了资源、难度和路径。
- “我们用了知识图谱，所以知识覆盖率高。”  
  必须给出覆盖率和路径合法性结果。
- “论文里达到 4.9% 幻觉率，所以我们也能达到。”  
  论文结果只能作为设计参考，不能当成本项目结果。
- “多模型都同意，所以判断正确。”  
  最新研究已经指出，跨模型一致性不等于效度。
- “AI 可以替代定制师。”  
  定制师承担最终责任，AI 只能做副驾。

## 十四、结论

最适合司南礼客的技术主张不是“我们做了十个 Agent”，而是：

> 用符号化业务流程约束生成，用学习者数字孪生驱动个性化，用知识图谱规划路径，用证据约束多智能体保证专业性，用真实业务交付物和长时程评估证明效果。

这就是从“赛题中间答案”走向“最终解决方案”的关键。

如果只能保留一句技术亮点：

> 司南礼客不是让大模型自由讲旅游，而是让大模型在真实业务流程、学习者状态和证据约束下，生成可验证、可追踪、可交付的专业训练内容。
