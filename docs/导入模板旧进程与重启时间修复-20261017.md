# 导入模板报错修复

2026-10-17

## 原因

截图报错“未知交付物: import-template”。运行中的后端仍为 12:45 启动的旧进程，其 OpenAPI 中缺少导入模板和画像历史接口；前端已通过开发服务加载新按钮，因此请求匹配到旧的普通文件提交路由。

重载时进一步发现，PowerShell 7 的 `ConvertFrom-Json` 已把 ISO 启动时间转换为 DateTime。启动脚本再把该对象转成普通字符串，会丢失时区信息并重复减去本地偏移，导致时间差为八小时，阻止了原有进程身份校验。

## 修复与生效

- 启动时间是 DateTime/DateTimeOffset 时直接保留类型换算；字符串按 RoundtripKind 解析，兼容 Windows PowerShell 5.1。继续核对原有 PID、端口、模式、数据库和启动时间，不绕过校验。
- 保留启动脚本的 UTF-8 BOM。
- 页面识别旧后端的特定报错，改为明确的重载提示，保留填写内容。
- 备份数据库后，用现有启动脚本的 `-Mode Normal -WebOnly -RestartBackend` 重载了已核验的普通后端。前端服务和原桌面窗口复用。

## 核对

重载后的后端及前端代理 OpenAPI 均包含导入模板接口，画像历史接口也已加载。普通实例沿用 `.dsh-run/normal/preview.sqlite`。

只读核对确认重载前后账号、订单、已提交文件、画像记忆和会话数量一致；草稿表与画像快照表已创建。未触发文件导入、提交投递或测试通话。前端类型检查和生产构建通过。
