## 2. 用户最核心的项目判断

用户明确提出：

> 赛题非常清晰，但赛题相当于一个“中间答案”，不是最终解决方案。我们要对着赛题，补全“问题痛点—赛题要求—解决方案”，把项目的问题痛点和解决方案完美嵌合到赛题要求上。汇报时讲问题痛点和解决方案，形成一个完整故事，同时自然呼应赛题。

因此，项目叙事必须是：

```text
真实行业问题
  ↓ 旧办法为什么失效
赛题给出的中间答案
  ↓ 落到入境游具体岗位
司南礼客最终解决方案
  ↓
可运行、可量化、可追溯、可迁移的培训闭环
```

不能在答辩中逐条说“赛题要求三个 Agent，所以我们做了十个 Agent”“赛题要求个性化，所以我们做了画像”。这些说法是在回答中间答案，没有解释为什么现实必须这样做。

## 3. 项目一句话定位

> 入境游最贵的不是生成一份路线，而是有人对整趟旅程负责。司南礼客不训练一个更会聊天的 AI，而是把优秀定制师的经验变成可复制、可验证、可持续更新的训练系统。

另一句备用表达：

> 讯飞等平台提供通用智能，司南礼客把通用智能变成可交付的职业能力。

产品卖的不是一份行程，而是一支能接单、能负责、能规模化培养的入境游定制师队伍。

## 4. 为什么训练人，而不是直接做面向游客的 AI

这是老师从初赛到复赛反复追问的问题，必须成为主稿中的明确一页。

核心回答：

> 游客购买的是一套有人负责的完整交付，不是一份静态行程。纯 AI 规划器可以降低信息获取成本，但不能承担安全、改签、资源失效、纠纷和赔付责任。因此我们训练能够承担结果的定制师，AI 做副驾，不替代责任主体。

入境游定制师的定义：

- 在线接单；
- 识别游客真实需求；
- 设计跨城市、跨资源的完整方案；
- 协调酒店、车队、票务、地接、导游等资源；
- 处理行中变更和突发事件；
- 对最终服务结果负责。

不能把项目讲成一个面向游客的攻略生成器。

## 5. 赛题真正要求的四件事

### 要求一：真实垂直技能场景

- 面向真实岗位任务，不是泛知识问答；
- 明确体现不同背景学习者的适配；
- 入境游是首个验证场景，不是系统边界；
- 要证明该场景复杂、高风险、知识密集，值得采用这套技术。

### 要求二：基于学情的个性化生成

- 建立学习者先验知识画像；
- 整合领域专业知识库；
- 生成至少三类资源：个性化讲义、实操指南、分阶测试题；
- 提供知识盲区、资源难度匹配曲线、学习路径图；
- 学员差异必须真正改变资源内容、难度和路径。

### 要求三：多智能体可信协同

- 至少三个职责明确的 Agent；
- 形成“分析—生成—校验—决策”闭环；
- 有辩论、交叉验证、冲突处理和最终裁决；
- 生成内容有证据来源；
- 对高风险内容有一票否决和人工复核；
- 支持动态追问和启发式导学；
- 符合数据合规和伦理要求。

### 要求四：可反馈、可验证、可落地

- 答题和交互反馈必须改变资源难度或学习路径；
- 答错降维解释，答对进阶挑战；
- 更新画像、知识库和训练案例；
- 提供可视化决策报告；
- 系统可部署、可运行、有源码、部署说明和单元测试；
- 竞赛指标：幻觉率低于 5%，画像资源适配准确率不低于 85%，核心知识点覆盖率不低于 90%；
- 至少三类学习者画像、至少一个领域知识库切片、建议准备 50 个以上测试案例；
- 具备领域迁移能力。

记忆短句：

> 真场景、真学情、真协同、真验证。

## 6. 三个真正的痛点

### 痛点一：优秀定制师经验难复制

- 入境游定制师的核心能力是判断，不是背知识；
- 要同时判断需求、资源、路线、文化、风险和交付责任；
- 经验主要存在成熟定制师脑中，传统课程和师傅带教无法规模化；
- “人才数量不足”是结果，不应单独作为独立痛点。

### 痛点二：学员差异大，统一训练无法形成真实能力

- 文旅专业、计算机背景、语言跨文化背景的薄弱项完全不同；
- 统一课程会让学员重复学习已经会的内容；
- 真正薄弱的部分被留到真实订单中暴露；
- 系统必须知道每个人差在哪、下一题该难还是该易。

### 痛点三：高风险内容不能试错

- 历史叙事、宗教习俗、饮食禁忌、敏感场所、安全应急等内容容错率极低；
- 单模型同时追求个性化和专业性会发生冲突；
- 放开限制容易失真，严格限制又容易模板化；
- 必须有知识库约束、证据核验、交叉审查、风险否决和人工复核。

## 7. 两层个性化与反馈闭环

### 学员个性化，主层

- 诊断学历背景、理论测试、任务表现、知识盲区和技能弱项；
- 生成个性化学习路径；
- 资源难度动态调整；
- 这是赛题真正要求的个性化主层。

### 游客业务个性化，场景层

- 根据国家、年龄、家庭结构、文化背景、宗教饮食和风险偏好生成方案；
- 文化桥属于这一层；
- 它服务于定制师训练，不替代学员个性化。

### 真实反馈个性化，更新层

- 收集游客满意度、行程变更、投诉、事故和定制师复盘；
- 脱敏后转为结构化案例；
- 人工审核后更新知识库、评分规则或训练案例；
- 记录版本变化并跑回归测试；
- 不宣称把真实反馈直接写入模型记忆。

## 8. 解决方案架构共识

### 前台展示四个核心角色

1. 学情诊断 Agent：识别知识盲区和能力弱项。
2. 领域生成 Agent：基于领域知识生成讲义、实操指南和分阶题。
3. 审核纠偏 Agent：事实核验、文化风险审查、矛盾检查，拥有否决权。
4. 调度决策 Agent：决定角色顺序、资源难度、是否返工，并记录理由。

当前产品文档中存在“9 类 AI 角色”，当前 PPT 中存在“10 类 AI 角色”的口径。答辩前台建议只展示四个核心角色，其他角色作为后台能力；现有角色数量必须在 PPT、PRD 和口播中统一。

### 技术原则

- Agent 之间有明确输入、输出、证据、置信度、失败条件和责任边界；
- 由调度器统一编排，Agent 不直接互相调用；
- 使用共享黑板、任务计划、Trace 和证据台账；
- 生成侧放个性，校验侧守住专业；
- 六帽审查落到事实核验、风险审查、交叉质询和最终裁决；
- 高风险内容红黄绿分级，红色一票否决或转人工。

### 当前代码中的已确认架构

来自 `docs/Multi-Agent-Orchestra-架构.md`：

- 确定性编排的 Multi-Agent Orchestra；
- Conductor 负责顺序、依赖、黑板合并和 Trace；
- Score/Rubric、订单事实和教学资料构成输入边界；
- Agent 通过 Blackboard 共享状态，不直接互相调用；
- 教学、IM、电话实战共用同一注册表与编排入口；
- IM 对象明确区分 Conversation、Participant、Order anchor 和 Route；
- 评分、校准、资源事实和流程门控由领域服务控制，不交给 LLM 自由决定。

- Node.js >= 22.12.0，推荐 24.x；
- PowerShell 5.1 或 PowerShell 7。

首次换机安装/适配：

```powershell
Set-Location 'D:\司南礼客-交接包-202610171532\司南礼客-交接包-20261017\司南礼客-交接包-20261017'
powershell -NoProfile -ExecutionPolicy Bypass -File .\_交接文档\首次安装与适配.ps1
```

标准演示模式（固定案例，工作人员入口）：

```powershell

```

普通模式：

```powershell
.\司南礼客桌面版.bat
```

注意：

- `一键启动.bat` 是历史 web 开发入口，不应当作桌面演示入口；

## 11. 老师录音中的核心意见

已从会议录音中提炼，保存在独立文件中。主要观点：

1. 必须解释为什么训练定制师，而不是直接做 C 端 AI 规划器。
2. 定制师是旅行管家，对全程负责，不是普通导游。
3. 三个痛点有重叠，必须重新归并。
4. 个性化主层是学员，不是游客。
5. 多智能体不是为了数量，而是解决个性化与专业性冲突。
6. 必须正面回应幻觉、文化、宗教、意识形态和安全风险。
7. 真实服务反馈要汇聚成案例或规则，不直接写成个人模型记忆。
8. PPT 控制在 15 页左右，按“问题—技术—效果”讲。
9. 技术页左边简洁讲方法，右边讲指标和结果。
10. 视频要像实际应用片或广告片，不要做成访谈片。
11. 要讲清客户是谁、为什么付钱、商业价值如何形成。
12. 项目要有一条主线，不能所有模块平均用力。

## 14. 科大讯飞生态的定位

科大讯飞不是当前赛题发榜单位。只能作为可复用的技术/生态资源，未经授权不能宣称官方合作。

可结合的资源：

- 讯飞星火大模型；
- 讯飞开放平台；
- 智慧教育；
- AIUI；
- 虚拟人交互平台；
- 多语种语音识别、合成与翻译；
- 星火企业军团；
- 文旅大模型相关案例。

推荐定位：

> 讯飞提供通用智能，司南礼客把通用智能变成可交付的职业能力。

可补的生态空档：

- 从单点模型/语音/翻译能力到垂直岗位训练闭环；
- 从通用因材施教到高风险职业技能训练；
- 从文旅内容生成到定制师能力培养；
- 从通用 Agent 平台到可复制的行业岗位模板；
- 从普通聊天工具到可审计、可复核的可信 AI。
