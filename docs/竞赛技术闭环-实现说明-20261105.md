# 竞赛技术闭环实现说明

日期：2026-11-05
范围：把“专家经验难复制、学情难适配、高风险知识易幻觉、能力难复利”接到现有产品代码，而不是只做汇报图。

## 1. 已落地链路

专家经验
→ 可执行技能图（任务/方法/知识/证据要求/反例边界）
→ 生成上下文中的图约束
→ Claim 级证据闸门
→ 服务端官方来源快照
→ 高风险来源等级治理
→ BKT 答题后验更新
→ 学习信号回流
→ 错误模式与技能资产候选

## 2. 四个核心模块

### 2.1 经验编译器 / 技能图

- 编译来源：61 个技能点契约、Rubric、data/knowledge 下的知识文件。
- 当前产物：61 个节点、541 条边、412 条证据要求、31 个高风险节点。
- 每个节点包含：前置技能、执行方法、知识点、证据要求、正例、反例、证据来源。
- ThreadContext 会把根节点及一跳前置注入生成上下文，并在 render 中输出“技能图约束”。

### 2.2 Claim 级证据闸门

- 先把生成内容拆成 claim，再检查词项覆盖、数字一致性和风险等级。
- 高风险 claim（签证、入境、海关、保险、安全、宗教、法律等）只接受：
  - official：政府/监管机构/官方政策；
  - curated：项目内审阅过的 Rubric/技能图/专家契约；
  - observed：系统内直接记录的订单、通话、交付物行为。
- 百度百科、知乎、视频、公众号等 secondary 来源，即使词项高度重合，也不能单独放行高风险结论。
- 信任等级由服务端根据 source 重新判定，客户端传入的 trust 字段不能升级来源。
- 结论为 human_review 时进入人工复核，不冒充 NLI 或“自动证明真相”。

### 2.3 官方来源真实性

- 官方 URL 由服务端抓取正文并写入 `source_snapshot`，不信任客户端自算哈希。
- 快照保存 canonical URL、host、正文、SHA256、抓取时间、MIME、原始大小和抓取方式。
- 回查时重新计算 SHA256；正文被篡改、来源域名不在白名单或快照状态异常时直接拒绝。
- 官方 claim 必须在快照正文中定位到证据片段，不能只提交“看起来像官方链接”的 URL。
- 抓取边界：仅允许 http/https、官方白名单域名、标准端口、公网 DNS、官方域名重定向；最大 2 MB，10 秒超时，只接受 HTML/XHTML/纯文本。
- 严格来源校验已接入生成交付物、实战评分与 `/competition/evidence/verify`。

### 2.4 BKT / 主动诊断

- 答题不再使用固定加减分，而是完成 BKT 后验更新并写入教学掌握概率。
- 学习路线同时输出前置约束、Expected Information Gain 和 next-best-probe。
- 同一道题重复提交会被拒绝，不重复写 attempt、掌握度或学习信号。

### 2.5 反馈回流 / 能力复利

- 答题和实战评分都会编译 learning_signal。
- 反馈信号经过错误模式聚合后生成 pending_expert_review 的技能资产候选，不直接改写技能图。
- 竞赛接口按当前登录用户读取反馈候选，不做跨用户聚合。

## 3. 业务真实性补强

### 3.1 客户事实卡

- 客户卡区分 fixed / canonical_hidden / unknown；未知项明确显示“没有确定”，禁止补造人数、日期、价格和身份结论。
- 订单 payload 中用户已明确写入的字段优先于旧卡派生值。
- 同一订单只更新阶段或状态时保留客户卡；客户、目的地、客源、语言、年龄、性别或证件发生变化时，旧卡立即失效并重建，避免跨场景复用订单号时把上一位客人的隐藏诉求带到新订单。

### 3.2 成本与交付物

- 地接组合报价缺少“用车”字样时，会从含“车/座”的车型报价中识别用车成本，避免漏算。
- 模板导入仍保留真实业务的客户联系人门槛；只有无实战上下文的纯模板导入测试不伪造联系人，也不把测试便利带进真实调用。

### 3.3 订单管理

- 普通阶段 0 派单只在消息中心出现。
- 已经进入后续阶段的演示订单，即使 `grab` 动作是种子补录，也进入订单管理供复盘。
- 禁用/取消的历史订单可复盘，但不混入待抢派单。

## 4. 可用接口

- POST `/competition/evidence/snapshots`：服务端抓取官方页面并保存快照。
- GET `/competition/evidence/snapshots/{snapshot_id}`：回查快照并复算完整性。
- GET `/competition/skill-graph/summary`
- GET `/competition/skill-graph/{skill_point_id}`
- POST `/competition/evidence/verify`
- GET `/competition/diagnosis/next`
- GET `/competition/feedback/candidates`
- GET `/competition/overview`

所有接口都依赖当前登录用户；未登录请求返回 401。

## 5. 验收状态

最近一次全量回归：`412 passed`。

已通过：经验编译器、证据闸门、服务端来源快照、BKT、能力复利、教学线程、学习路线、实战完成、竞赛 API、客户事实卡、成本核算与模板导入回归。

重点回归覆盖：

- 高风险 claim 被百科类来源阻断；
- official / curated / observed 来源可支持高风险 claim；
- 客户端伪造 trust 不能绕过来源治理；
- 官方来源缺少服务端 snapshot_id 或证据片段时被阻断；
- 快照正文篡改后完整性校验失败；
- 技能图一跳前置、上下文约束和来源等级；
- 第二稿返工后，证据审计针对最终正文重新计算；
- 答题后生成 BKT 诊断与唯一学习信号；
- 竞赛 API 的认证、技能图、证据校验和来源策略；
- 客户显式字段覆盖旧卡、未知字段不被编造、身份变化使旧卡失效；
- 地接组合报价中的车型成本不漏算。

## 7. 明确边界

当前证据闸门是“可复现的词项/数字/来源治理闸门”，不是语义蕴含模型，也不是“官方来源伪造已彻底解决”。后续若要提高同义改写的召回，应在同一接口后接入 cross-encoder / NLI，并单独做标注集评估。
