# 语音首呼身份修复

## 问题与原因

抢单界面和拨打前的客户资料读取原始订单中的客源地。拨打语音时，接口把公开的平铺 `order_detail` 交给 `VoiceBridge`，该对象没有原始订单的 `payload`。

语音模块随后按数据库原始行解析资料，读不到客源地、语言、明确性别/年龄和其他需求，客源地与语言回落到“香港、中文”。前端收到语音 `ready` 事件后又用该人设覆盖原有展示，出现拨打前后身份变化。

公开资料还有一处独立遗漏：即使订单明确写了年龄或性别，也会使用按订单号派生的值；模型人设却采用订单明确值，造成界面和声音不一致。

## 本次修复

- 语音接口把原始订单行传入 `VoiceBridge`，仅额外补当前阶段名称；完整私有人设保持在后端内部。
- `VoiceBridge` 拒绝缺少原始 `payload` 的输入，避免格式错误被静默补成香港客户；错误由原有语音异常处理回传。
- 公开年龄、性别优先采用订单明确值，缺失时继续按订单号稳定派生，与模型人设和音色选择保持同一口径。
- 未修改已有订单、账号、数据库或对话记录，也未将私有人设加入公开详情。

缺少明确性别时，同一订单仍使用固定的派生性别，重新拨打不会随机改变性别。

## 加载修复

结束当前通话后，在项目根目录双击 `重启司南礼客.bat`，再重新拨打。已有通话不会自动替换人设。

本轮只做订单资料的只读核对、源码复核与静态语法解析；按用户要求未启动软件、未运行测试或调用外部模型。
