# 演示账户：移除 new，新增空白学员

2026-10-19

## 账户

- 移除遗留账号 `new`（连同其订单、学习、画像、会话数据）。
- 新增空白演示账号：
  - 用户名：`demo-blank`
  - 口令：`Demo2026!`
  - 展示名：`新学员 · 空白画像`
  - 类型：`demo`

## 状态规则

- 每次登录 `demo-blank` 时，清空该账号的订单、学习记录、能力表、画像基线与快照、线程、记忆和会话数据。
- 退出登录时再次清空，保证下一次进入仍是完全空白。
- 进入后 `has_profile_data=false`、`has_initial_assessment=false`、`can_assess=true`、订单数为 0，首页/画像页会引导填写初始画像。
- `demo-flow` 仍是原来的三阶段订单演示账号，不受影响。
- `demo-flow` 退出重置后的订单状态：云南单阶段 1；周先生单阶段 4（行前出团通知，资源已锁定，出团通知书尚未发送）；四川单阶段 7（已完成待评分）。周先生单固定发送出团通知书后才推进到阶段 5，并触发司导群车辆故障事件。
- 车辆故障注入后，学员第一次在司导群回应时，司机会补一条一次性的换车结果：「替换车 7:20 到酒店，8 点出发；400 元由车队承担」，同时把车队状态从“无档期”更新为“可用”。之后不会重复补发，也不会一直重复“7 点前给准信”。

## 实现

- `tripcraft/services/demo_blank_state.py`：空白账号常量、`reset_blank()`、`ensure_account()`。
- `tripcraft/api/routers/auth.py`：登录/退出时对 `demo-blank` 执行空白复位。
- `tripcraft/services/auth_service.py`：演示账号在登录列表置前，且不显示账户类型后缀。
- `scripts/prepare_demo_accounts.py`：一次性移除 `new`、创建/复位 `demo-blank`。

## 验证

普通实例实时接口验证：登录账户列表包含 `demo-flow`、`demo-blank`，不再包含 `new`；登录和退出重登后 `demo-blank` 均为 0 订单、0 能力记录、可做初始测评。`demo-flow` 仍有 3 张演示订单，其中 `9920000000000003` 为已完成待评分订单。
