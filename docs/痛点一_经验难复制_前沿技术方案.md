# 痛点一研究：专家经验难复制

> 日期：2026-11-03  
> 目标：把“优秀入境游定制师的经验难复制”做成一张有技术复杂度、术语密度、真实原理和亮眼成效的主稿页面。  
> 说明：文中论文指标均为外部研究结果，不是司南礼客实测结果。

---

## 一、这一痛点一句话讲清

> 定制师真正值钱的是“看什么线索、在什么条件下做什么判断、哪些情况绝不能做什么”的经验，而不是背景点知识。传统课程只能复制显性知识，无法复制专家的判断过程。

具体表现：

- 新人的需求访谈是机械提问，成熟定制师能从一句模糊描述中判断真实偏好和风险；
- 新人的方案是景点拼接，成熟定制师会权衡路程、预算、体力、季节和资源兑现；
- 新人看到的是“正常流程”，成熟定制师知道“哪里最容易出错、出错后先做什么”；
- 这些判断散落在访谈、历史订单、复盘、群聊和师傅脑中的隐性知识里，没有被结构化。

赛题对应考点：

- 领域专业知识库；
- 个性化资源生成；
- 至少三种资源形态；
- 高保真知识；
- 知识覆盖和可追溯。

---

## 二、为什么普通 RAG 不够

普通 RAG 做的事是：

```text
文档切块 → 向量召回 → 拼进提示词 → LLM 回答
```

它有三个致命问题：

1. **只有知识，没有判断**：能召回“故宫开放时间”，不能召回“带老人时为什么不应该把故宫和长城排在同一天”。
2. **只有结论，没有边界**：能说“穆斯林不吃猪肉”，但不知道具体沟通方式、替代方案和禁忌边界。
3. **只有相似，没有因果**：能找相似段落，不能解释任务、方法、条件和结果之间的关系。

所以第一痛点不能只讲“我们用了 RAG”，必须讲：

> 把专家经验编译成可推理、可追溯、可生成的知识结构。

## 三、前沿研究给出的三条支撑

### 1. KUPAS MASTER：把师傅的隐性经验蒸馏成 Agent 可用资产

核心做法：

- 从工作记录和专家访谈中提取六类案例要素：
  - Context：情境
  - Cues：线索
  - Judgment：判断
  - Action：行动
  - Boundaries：适用边界
  - Outcomes：结果
- 再将经验组织成六类资产：
  - Rules：规则
  - Constraints：约束
  - Best practices：最佳实践
  - Negative examples：反例
  - Corner cases：边角案例
  - Skills：可调用技能
- 通过语义对齐、个体经验蒸馏、组织级合并和交叉复核保留来源证据与未解决分歧。

论文报告：

- 通用模型：70.63 分；
- 原始语料 RAG：79.75 分；
- KUPAS MASTER：89.58 分；
- 相比原始 RAG 提升 9.83 分，且在 7 个评分维度上均有提升。

这不是“多给点上下文”，而是“把经验组织成可执行知识”。

参考：KUPAS MASTER, arXiv:2609.37673。

### 2. TMK / Ivy：用符号任务模型约束 LLM，让它解释“怎么做”和“为什么”

TMK 是 Task-Method-Knowledge：

- Task：目标是什么；
- Method：用什么方法完成；
- Knowledge：为什么这样做、需要什么条件。

它把技能拆成层级任务、方法选择、因果链和适用条件，再让 LLM 在结构约束下生成解释。

研究结果：

- AI 辅助的 Text-to-Model 方法把专家建模时间降低 50%—70%；
- 在 PlanBench 的 opaque symbolic Blocksworld 任务中，TMK 结构化提示把准确率从 31.5% 提升到 97.3%；
- 在 Ivy 中，符号约束提升了“how/why”问题解释的结构质量。

这说明：

> 不是让模型自由讲经验，而是让模型沿着“任务—方法—知识—条件”的结构讲经验。

参考：

- Ivy, arXiv:2511.20942；
- AI-assisted Text-to-Model, arXiv:2604.17624；
- Knowledge Model Prompting, arXiv:2602.03900；
- Enhanced Skill QA with TMK, arXiv:2504.07463。

### 3. MAGG / GraphRAG：让知识图更有治理和全局结构

MAGG 提出“治理式知识图”：

- 每个实体和关系都有来源；
- 每条事实有 owner；
- 每条三元组经过证据审查后才能入库；
- 问答时路由给领域图专家，而不是无差别召回。

论文报告：

- 严格三元组 F1 相比平铺插入提升 47%；
- 映射三元组 F1 提升 51%；
- 在 MuSiQue 上比 Microsoft GraphRAG 高 9.0 EM、11.2 token-F1。

GraphRAG 则把文档建成实体图，并预生成社区摘要，适合“全局问题”和跨文档知识组织。

参考：

- MAGG, arXiv:2608.28642；
- GraphRAG, arXiv:2404.16130。

## 四、我们的技术方案：Expertise Compiler

建议把第一痛点技术亮点命名成：

> **Expertise Compiler：专家经验编译引擎**

它的核心不是“知识库”，而是把专家经验变成机器可执行的知识资产。

### 四阶段流程

```text
专家访谈 / 历史订单 / 复盘录音 / SOP / 反例 / 群聊记录
        ↓
① 经验抽提：六元认知案例
Context → Cue → Judgment → Action → Boundary → Outcome
        ↓
② TMK 建模：Task → Method → Knowledge
任务分解、方法选择、条件、因果、例外
        ↓
③ 治理式技能图谱
技能节点 + 前置边 + 证据边 + 风险边 + 版本 + 专家 owner
        ↓
④ 图约束生成
混合检索 → GraphRAG → 约束改写 → 多角色生成 → 证据核验
        ↓
个性化讲义 / 实操指南 / 分阶测试题 / 案例解释 / 复盘建议
```

### 四个关键模块

#### 模块 1：经验抽提

输入：

- 20—30 个真实订单；
- 5—8 位定制师访谈；
- 师傅的问答记录；
- 行中事故和复盘；
- 现有 SOP、资源报价和课程材料。

输出：

- 六元经验卡：情境、线索、判断、行动、边界、结果；
- 反例和边角案例；
- 每个经验卡的来源和时间。

#### 模块 2：TMK 任务建模

把每个步骤拆成：

- 任务目标；
- 可选方法；
- 方法选择条件；
- 所需知识；
- 失败模式和边界；
- 结果评价标准。

例如：

```text
Task：带老人和孩子的北京三日游
Method A：故宫 + 景山 + 北海
Condition：体力中等、天气良好
Method B：故宫 + 胡同 + 亲子体验
Condition：孩子较小、步行耐力差
Knowledge：开放时间、步行距离、预约规则、餐饮偏好
Failure：行程过密、午休不足、票务未落实
```

#### 模块 3：治理式技能图谱

节点：

- Skill：技能点；
- Task：业务任务；
- Method：方法；
- Case：经验案例；
- Evidence：证据；
- Risk：风险；
- Resource：训练资源。

边：

- prerequisite；
- belongs_to；
- supports；
- conflicts_with；
- applies_under；
- evidence_for；
- risk_of。

每个节点带：

- source evidence；
- owner；
- confidence；
- version；
- review status；
- applicable scope。

#### 模块 4：图约束生成

流程：

```text
画像 + 当前技能点
  → BM25 精确检索
  → Dense 向量召回
  → Cross-Encoder 重排
  → GraphRAG 子图扩展
  → 约束改写
  → 生成讲义/指南/题目
  → claim-level 核验
```

生成不是自由写，而是满足：

- 必须覆盖的任务节点；
- 必须解释的方法和条件；
- 必须给出的反例；
- 必须引用的证据；
- 禁止越过的风险边界；
- 当前学员的难度和表达偏好。

## 五、为什么这套方案听起来“前沿”

因为它同时踩中四个技术关键词：

1. **Tacit Knowledge Distillation**：把隐性经验蒸馏成可复用资产。
2. **Neuro-Symbolic Modeling**：符号任务结构 + 神经生成。
3. **Governed Knowledge Graph**：知识图谱带 owner、证据、版本和治理。
4. **Graph-Grounded Generation**：图结构约束检索和生成。

并且不是把术语拼在一起，而是每个术语都有对应的工程对象：

- 六元经验卡；
- TMK 模型；
- 技能图节点和边；
- 证据台账；
- 版本和 owner；
- 生成约束模板。

## 六、如何给评委讲懂

### 第一层：业务解释

> 过去培养一个成熟定制师，主要靠师傅带。师傅不只是告诉新人“这个城市有什么”，而是告诉他“听到什么话要追什么、什么情况下不能用这个方案、出了问题先找谁”。我们要做的，是把这些判断过程从人脑里抽出来，变成机器可训练的知识。

### 第二层：技术解释

> 我们先把专家访谈和真实订单拆成六元经验卡，再编译成任务—方法—知识模型，最后固化成带证据、带边界、带版本的技能图谱。生成资源时，大模型只能在这个图谱约束下组织内容，不能自由发明专业结论。

### 第三层：评委能看到的证据

> 同一份专家经验，普通大模型只给出知识点，我们的系统能生成“适用条件、操作步骤、异常处理、反例和判断依据”。我们可以展示三种资源、每一条证据来源，以及专家审核记录。

### 第四层：一句话总结

> 我们不是把旅游资料喂给大模型，而是把师傅的判断编译成一套可训练、可生成、可审计的专业知识系统。

## 七、亮眼效果应该怎么设计

### 不建议对外直接承诺的假指标

- “准确率 99%”；
- “效率提升 100 倍”；
- “完全替代师傅”；
- 直接引用论文的 89.58 分说成自己的结果。

### 建议先做实测，再放到PPT

用 20—30 个真实任务做专家盲评，比较：

- B0：通用大模型；
- B1：普通 RAG；
- B2：经验卡 + 普通生成；
- B3：Expertise Compiler 完整方案。

### 建议的目标指标

- 专家经验规则覆盖率≥95%；
- 核心知识点覆盖率≥95%；
- 专家一次通过率≥90%；
- 资源结构完整率≥95%；
- 单份个性化资源生成时间下降≥80%；
- 专业任务评分相比通用模型提升≥15 分；
- 相比普通 RAG 提升≥8 分。

### PPT右侧两张“战报卡”可以这样写

> **专家经验覆盖率**  
> **95%+**  
> 由六元经验卡+技能图谱验证

> **专业资源一次通过率**  
> **90%+**  
> 双专家盲评，普通RAG为基准组

如果最终实测达到更高，再替换成真实数字。数字必须来自自己的测试。

## 九、答辩追问

### Q1：这不就是知识库/RAG吗？

回答：

> 普通RAG检索的是段落，我们检索的是任务、方法、条件、反例和证据构成的结构化经验。模型不是自由拼接文本，而是在技能图约束下选择方法、解释条件、给出反例。

### Q2：专家经验怎么保证抽对了？

回答：

> 我们不是让模型一次抽完就信。每条经验卡都保留原始来源，经过专家审核、冲突标注和版本管理；未通过审核的内容不能进入生成知识图。

### Q3：为什么要TMK，不直接让大模型生成？

回答：

> 因为大模型擅长流畅表达，不擅长稳定表达“为什么、在什么条件下、什么情况不能做”。TMK把任务、方法和知识显式化，LLM只负责把结构说清楚。

### Q4：为什么需要知识图谱？

回答：

> 专家经验不是孤立事实，而是有前置关系、替代方法、例外和风险。图结构能支持多跳检索、路径规划和冲突检测，普通向量库只能做相似度匹配。

### Q5：效果怎么证明？

回答：

> 用同一批真实任务，比较通用模型、普通RAG、经验卡方案和完整方案；由两名以上行业专家盲评，并报告覆盖率、一次通过率、任务得分和生成时间。
